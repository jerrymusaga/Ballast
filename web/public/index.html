Hide the portfolio

Nobody front-runs you. But nobody can tell whether you followed the strategy either, so they are back to trusting you.

Canton discloses per party, so the two come apart. The mandate lives in a contract the ledger reads and nobody else does. The strategy stays private and still binds — a rebalance that breaks it does not commit, so investors get proof without disclosure.

What makes it binding

Hiding a portfolio is old — semi-transparent ETFs have done it for years. What they cannot do is prove the strategy was followed without showing you the strategy.

Real assets

The vault holds genuine CIP-56 registry instruments. Ballast defines no asset of its own — the deployed package contains no token template at all.

The ledger decides

Nine ways to deviate are refused outright: trading before the band is breached, under-trading, trades that aren't self-financing, prices away from the oracle, breaching the cadence floor.

Proof, not trust

Each rebalance emits a compliance record citing the mandate version it satisfied — and no weight, instrument or counterparty. The manager cannot forge one alone.

Honest limits

The registry sees its own instrument. Published NAV inverts given enough observations. The counterparty knows the trade. All stated, none hidden.

Verify it in five minutes

Every claim on this site is checkable from the repository. Nothing below needs an account, a key, or our help.

01

The privacy claim, on a real ledger

Open the Lenses tab. The investor sees the fund and the disclosed bounds; the Mandate holding the target weights is absent. Those counts are live active-contract-set answers from a running participant node.

02

The assets are real, and the package proves it

Ballast builds against the Canton Token Standard interfaces, and the deployed package contains no token implementation — so it cannot be minting its own pretend assets.

unzip -l ledger/ballast/.daml/dist/ballast-0.1.0.dar | grep dalf
03

The mandate refuses

The policy suite is mostly refusals: each differs from a known-good rebalance in exactly one dimension, and the suite ends by re-running the good one so nothing passes for an unrelated reason.

cd ledger && daml build --all && cd ballast-test && daml test
04

The keeper agrees with the ledger

The off-ledger watcher computes trades in exact fixed-point arithmetic, matching Daml's Decimal rather than using floats — so a rebalance is never rejected for a rounding error nobody can see.

cd keeper && npm test
05

Read what we don't claim

The README carries the limits as prominently as the claims: the oracle is trusted, published NAV inverts given enough observations, and the rebalance counterparty necessarily learns the trade.
